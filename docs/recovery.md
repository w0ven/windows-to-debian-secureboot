# 故障与恢复

## 先判断在哪一步，不要连续重跑

| 现象 | 含义与处理 |
| --- | --- |
| `Check` 拒绝平台、网络、ESP 或加密状态 | 当前版本不支持或无法安全识别。不要修改检测条件硬上。 |
| 下载 404 / SHA-256 不一致 | 固定材料已下架、上游改变或下载损坏。停止，使用经过验证的新项目版本；不删除校验。 |
| 旧版在 `Get-Partition -DriveLetter S` 或 `Get-Volume -DriveLetter S` 报找不到对象 | 某些 Windows 的 EFI 临时挂载可读，但 Storage 不登记盘符。新版按原生卷路径映射并继续核验磁盘/GPT 身份。保留暂存；确认没有本工具的启动项、EFI 文件和状态后，归档旧暂存，再用新版源码准备；不要跳过核验或盲目重跑。 |
| EFI 空间不足 | 不会自动调整分区。请使用更合适的镜像/商家安装方式，或由了解布局的人单独处理分区。 |
| 固件写入返回拒绝/权限/认证错误 | Windows 管理员权限不足以保证固件接受更新。停止，不尝试删除 PK/KEK 或取消签名校验。 |
| 提示 staging 已存在 | 上次可能部分完成。先保留工作目录，读状态及实际固件启动项，不要直接删目录再运行。 |
| 重启后 RDP 不通，SSH 也不通 | 可能仍在引导、网络/SSH 失败或被固件拒绝。不能仅凭端口拒绝判断清盘完成或磁盘损坏。 |
| 约 10 分钟后回到 Windows | 测试未被 hold/放行且软件回退执行。Windows 未被正式安装流程清除。 |
| 等待后仍无 RDP/SSH | watchdog 可能未运行或重启失败。使用商家控制台/强制重启，必要时让商家恢复；继续等待不是恢复方案。 |
| 安装后 root 连不上 | 看商家控制台、SSH 端口/安全组、网络配置、安装日志。不要假定旧 Windows 还存在。 |

## Windows 还在：取消本工具试启动

从原项目目录，在管理员 Windows PowerShell 执行：

```powershell
# 如果 15 秒 Windows 重启计时已经开始：
shutdown /a

# 然后取消本工具自己的启动项并检查/移除对应试启动文件：
.\Restore-WindowsBoot.ps1
```

恢复脚本会核对原 ESP GUID、原 Windows boot manager 哈希、测试 Boot 项内容，以及将删除的每个文件的哈希。遇到不同的 BootNext、不同文件或不同 ESP 会停止，不会把它们当成自己的内容删除。

它将工作目录移到 `%ProgramData%\W2D-cancelled-时间戳`，保留备份和诊断资料；该目录仍含密码散列，不要公开上传。确认已取消成功后，才可以从头准备新一次 Test。

如果准备工作在 `state.json` 建立前就失败，恢复脚本会明确拒绝。此时保留 `%ProgramData%\W2D`，确认固件里没有本次 BootNext、ESP 没有本次文件后，再由管理员处理该目录。**没有状态文件不等于可以直接假定系统没被改变。**

只执行 `shutdown /a` 不会清除 BootNext；之后的下一次重启仍可能进入测试或自动安装。

## 试启动 Linux 还能 SSH

```sh
# 明确接管，暂停试启动超时回退；这不是清盘确认。
/w2d/install-debian.sh --hold

ip -4 addr
ip -4 route
cat /proc/partitions
cat /var/log/syslog
```

不打算安装且尚未批准清盘时，可在检查未放行后正常重启，BootNext 已被固件消费，随后应走保留的 Windows 默认启动路径。若不能确定是否已放行分区，**不要强制重启**。

诊断日志可能含主机名、网络信息及安装配置。只分享必要的脱敏错误片段，不公开整个 initrd、配置目录或完整 Windows 备份。

## 已经放行安装

- 不要重复执行安装命令，也不要在写分区/文件系统时强制断电。
- SSH 断开可能是安装结束重启，也可能是故障；先确认机器实际状态。
- 清盘后原 Windows 和本机引导备份目录不再是恢复来源。恢复需要**事先保存到机器外**的系统/数据备份，或商家面板重装。
- root 密码是运行脚本时新设置的密码，不是任何写在本仓库里的默认密码。

## 关于主机密钥变化

安装环境与正式系统的 SSH 主机密钥不同。已有同 IP 的 SSH 记录还可能属于更早的系统。

先通过已信任的控制台、安装输出或其他可信渠道核对新指纹，确认本次重装已发生，再处理旧记录。`ssh-keygen -R` 只管理客户端记录，不是验证服务器身份的办法；不要用 `StrictHostKeyChecking=no` 掩盖未知身份。

## 微软 CA 更新为何不自动删除？

取消试启动只恢复启动选择与试启动文件，不把信任库回滚到旧快照。`db` 是全系统安全状态，后续 Windows 更新或其他软件可能也在使用新增 CA。未经明确评估的删除可能破坏其他启动路径，因此本项目不提供“一键撤销证书”。
